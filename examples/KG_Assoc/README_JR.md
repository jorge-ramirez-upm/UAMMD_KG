# Simulation steps

## Creation of initial configurations

- Use the code BulkStars 

```bash
./Bulk -h
Generate star polymers with terminal stickers and WCA solvent.

Usage: Bulk -nc=NC -na=NA -n=N [-rho=RHO] [-rhopoly=RHO]
            [-blength=L] [-seed=SEED]

  -nc=NC       Number of star molecules (required)
  -na=NA       Number of arms per star (required)
  -n=N         Beads per arm, including its sticker (required)
  -rho=RHO     Overall bead density (default 0.85)
  -rhopoly=RHO Target polymer-bead density (default 0.20)
  -blength=L   Bond length (default 0.97)
  -seed=SEED   Random-number seed

Atom types: 1 polymer, 2 terminal sticker, 3 WCA solvent.
```

- Some use examples: 

| $N_C$ | $A$ | $N$ | $\rho$ | $\rho_{poly}$ | Command                                    |
| ----- | --- | --- | ------ | ------------- | ------------------------------------------ |
| 1000  | 4   | 10  | 0.85   | 0.8           | `./Bulk -nc=1000 -na=4 -n=10 -rhopoly=0.8` |
| 1000  | 4   | 10  | 0.85   | 0.4           | `./Bulk -nc=1000 -na=4 -n=10 -rhopoly=0.4` |
| 1000  | 4   | 20  | 0.85   | 0.8           | `./Bulk -nc=1000 -na=4 -n=20 -rhopoly=0.8` |
| 1000  | 3   | 10  | 0.85   | 0.8           | `./Bulk -nc=1000 -na=3 -n=10 -rhopoly=0.8` |

where $N_C$ is the number of star molecules in the box, $A$ is the number of arms, $N$ is the length of the arms, $\rho$ is the overall density (including monomers and solvent particles), and $\rho_{poly}$ is the density of monomers. The generated files, in LAMMPS data format, have self-explanatory names about their contens (i.e. `Stars_NA4N10C1000rho0.85rhopoly0.8.lammpsdat`). 

In this project, the generated files must be moved to the folder `UAMMD_KG/examples/KG_Assoc/systems/generated`. In the project, this step is named **C1**. 

## Equilibration of monomer positions

This step starts from the configuration generated in the step C1. 

We use a modified slow push-off method (slightly different to the one used for linear chains). In this project, this is stage **E1**. Several observables are checked for convergence ($R_g$, arm end-to-end vector, max and min bond lengths, energies, pressure, etc).

Codex has created automatic scripts to start these runs (see file `examples/KG_Assoc/scripts/prepare_p42_c1_replicas.sh`). The raw command to equilibrate the monomer positions of the system `Stars_NA4N10C1000rho0.85rhopoly0.8.lammpsdat` using seed `12001` is:

```bash
examples/KG_Assoc/kg_assoc_star_equilibrate --input examples/KG_Assoc/systems/generated/Stars_NA4N10C1000rho0.85rhopoly0.8.lammpsdat --output examples/KG_Assoc/systems/e1_equilibrated/C1_long_s12001.e1.lammpsdat \
    --diagnostics examples/KG_Assoc/systems/e1_equilibrated/C1_long_s12001.e1.lammpsdat.e1_diagnostics --arms 4 --narm 10 --seed 12001 \
    --stage3b-steps 20000 --stage3b-diagnostic-every 500 --wca-ramp \
    --wca-ramp-steps 500 --promotion-steps 1000 --dt-dpd 0.002 --dt-wca 0.01 \
    --stage4-steps 2000000 --conformation-every 1000
```
with the following important command line parameters: 
- `input`: File equilibrated in C1.
- `output`: Final equilibrated file after E1
- `diagnostics`: File with data to evaluate if the equilibration was successful.
- `arms`, `narm`, `seed`: self-explanatory
- `stage3b-steps` and `stage3b-diagnostic-every`: Length and frequency of analysis for stage 3b (DPD relaxation/hold segment after the Stage-3 ramp and before WCA)
- `wca-ramp` and `wca-ramp-steps`: Do a WCA ramp with increasing values of $\epsilon$. 
- `promotion-steps`: WCA run at increasing $dt$ 
- `dt-dpd` and `dt-wca`: Time steps for long DPD and WCA sections
- `stage4-steps`: Final WCA equilibration steps 
- `conformation-every`: Frequency to save info for equilibration analysis.

## Equilibration of stickers

This step starts from the equilibrated configuration of step E1. 

We launch a long 6 million-step trajectory with $dt=0.01$, storing restart configurations at times 40000, 50000 and 60000. In the project, this is stage **E2**. From the same equilibrated configuration, 5 different chemical trajectories are generated by using different seeds (12001, 12002, 12003, 12004 and 12005). 

Codex has prepared automatic scripts to do this stage (see file `examples/KG_Assoc/run_p33_c1_restart_bank.sh`). The raw sequence of commands to create the restart configurations specified above, for seed 12001, is:

```bash
examples/KG_Assoc/kg_assoc_stars --input examples/KG_Assoc/systems/e1_equilibrated/C1_long_s12001.e1.lammpsdat --arms 4 --narm 10 --steps 4000000 --Nevery 100 --diagnostic-every 1000 --seed 12001 --output examples/KG_Assoc/systems/restart_bank/C1/C1_e2_s12001_t40000
examples/KG_Assoc/kg_assoc_stars --restart-prefix examples/KG_Assoc/systems/restart_bank/C1/C1_e2_s12001_t40000 --steps 1000000 --diagnostic-every 1000 --output examples/KG_Assoc/systems/restart_bank/C1/C1_e2_s12001_t50000
examples/KG_Assoc/kg_assoc_stars --restart-prefix examples/KG_Assoc/systems/restart_bank/C1/C1_e2_s12001_t50000 --steps 1000000 --diagnostic-every 1000 --output examples/KG_Assoc/systems/restart_bank/C1/C1_e2_s12001_t60000
```

## Automatic scripts

### Automatic equilibration 

- From the configurations generated with `BulkStars` to the C1 equilibrated, and to the restart bank: 

```bash
examples/KG_Assoc/scripts/prepare_p42_c1_replicas.sh 12003
```
where we specify the seed to be used for all the steps of the equilibration. 

- The final configurations in the restart bank can be validated via:

```bash
python3 examples/KG_Assoc/analysis/validate_c1_restart_bank.py \
  --bank-dir examples/KG_Assoc/systems/restart_bank/C1 \
  --seeds 12003 \
  --times 40000,50000,60000
```

The script is prepared for the configuration `Stars_NA4N10C1000rho0.85rhopoly0.8.lammpsdat`, but it can be easily changed. 

### Rheology pilot

From one of the restarts generated in the previous equilibration step, we can launch a long equilibrium simulation to extract rheological data ($G(t)$) and trajectories of the COM of the star molecules. We can specify several restart files:

```bash
P42_PILOT_STEPS=32000000 \
P42_PILOT_COM_EVERY=10000 \
P42_PILOT_DIR=p42_rheology_pilot \
  examples/KG_Assoc/scripts/run_p42_rheology_pilot.sh \
  examples/KG_Assoc/systems/restart_bank/C1/C1_e2_s12001_t40000 \
  examples/KG_Assoc/systems/restart_bank/C1/C1_e2_s12002_t40000 \
  examples/KG_Assoc/systems/restart_bank/C1/C1_e2_s12003_t40000 \
  examples/KG_Assoc/systems/restart_bank/C1/C1_e2_s12004_t40000
```

- Analysis of results

The following python script can be used to analyze the rheological data and extract information about convergence and error of $G(t)$ at different time lags. The "$RUN_DIR" is the directory where the *.stress_correlator files have been generated in the previous step.

```bash
python3 examples/KG_Assoc/analysis/analyze_p42_rheology_pilot.py \
  --output-prefix "$RUN_DIR/rheology" \
  "$RUN_DIR"/*.stress_correlator
```
