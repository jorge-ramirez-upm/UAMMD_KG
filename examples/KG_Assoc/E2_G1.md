# E2-G1: generalized authenticated E2 infrastructure

Implementation starts at `7ba1afa69a54d7a9c1ce188007016c767d841e94`, branch
`KremerGrest`. This milestone implements the user's 11 October 2026 scientific
instructions. It launches no MD or production. The final commit SHA is reported
in the task delivery; manifests created afterward pin that committed SHA.

## Adopted decisions

The 11 fresh geometry/Ee banks and their 33 E1 histories are those in
[E2_REMAINING_CAMPAIGN.md](E2_REMAINING_CAMPAIGN.md) and the unchanged
[frozen inventory](campaign/e2_remaining_inventory_20261011.json). Prepare them
at Ea=4, with each target Ee and the frozen dt/T/nu0/Nevery/cutoff/FENE/NVT
parameters. There is no chemistry ramp or velocity resampling. The original
E1 preparation seeds are provenance, not the new chemistry seeds.

The user has provisionally accepted the three corrected C1 endpoints at E2
step 8,000,000 for production initialization, qualified by slow network-topology
relaxation. The user explicitly permits their use at production Ea=6/8/10 after
an authenticated, tested parameter switch. The common q(Ea) factor cancels from
the forward/reverse Metropolis ratio at fixed configuration. This supports
sharing equilibrium distributions; exact full-integrator invariance remains a
numerical qualification, not a proven theorem. It does not justify sharing
states across Ee, geometry or concentration.

The local LAMMPS `feature/associating-stickers` reference remains SHA
`1c6faf70e94aef2389c208e8c80c60c084a96907`. Its pinned kinetics/pair source files
were inspected: exact finite-step q, pair ordering, shifted FENE without extra
WCA, reciprocal valence-one state, and r_assoc gating of both reaction
directions remain unchanged. The previous executed dimer/K1/S2 evidence and
corrected periodic candidate oracle described in the campaign plan remain the
validation hierarchy evidence. No new equilibrium or GPU result is inferred.

## Segment lifecycle

`campaign/kg_assoc_e2.py` supplies `build`, `prepare`, `launch`, `verify` and `status`.
An output is a **new direct child** of
`DATASET_ROOT/banks/e2_attempts/<geometry_Ee_bank>/`, for example
`weak_smoke_v1`, `initial_v1` or `extension_v2`. One immutable plan covers three
histories, each in `r001..r003`. Each extension is a new attempt with an explicit
`--parent-attempt`, incremented segment index, pinned predecessor plan and
completion records, retained chemistry seeds/counters/partners and absolute
steps. It never resumes or overwrites an incomplete directory. An incomplete
attempt needs investigation and a separately prepared/approved attempt.

A `build` action forces rebuilding all six affected targets with `make -B`,
retains build logs/compiler/source/executable hashes, and marks failures incomplete.
Preparation requires its matching `--build-evidence`; timestamp-based `make -q`
alone is not trusted after shared header changes.

Preparation also requires a clean committed tree, current executables, immutable
source/build/executable hashes and E1 review evidence. It authenticates the
active E1 states against the frozen inventory, including the RP060/r002 retry;
checks completion, velocities, geometry and FENE; runs host self-tests; and
records full commands, parameters, code SHA, dependency hashes, compiler/CUDA
versions and build commands. The dataset protocol and matrix must match.
Planning files do not constitute execution approval.

`e2_seed_map.json` fixes 33 distinct chemistry seeds across the 11 fresh banks.
An extension retains its history's chemical identity. Under an exclusive
preparation lock, fresh MD seeds are reserved by existing immutable plans;
effective 32-bit kernel seeds are checked for collisions with prepared segments
and retained C1 streams. The Python seed calculation is checked against the
C++ host query. Failed/unlaunched plans retain their reservations. Reusing an
E1 history in a new attempt is not an additional independent replica.

`approval.example.json` is always `approved=false`. Actual launch requires
`--execute` and a separate approval with `schema_version=1`, `approved=true`,
correct purpose (`e2_smoke` or `e2_segment`), exact plan SHA256, reviewer and
date. This is an explicit recorded attestation, not a cryptographic signature.
An ordinary segment additionally requires a completed capped oracle smoke with
identical source/executable hashes, parent hashes, chemistry and frozen physics.
Every restart path needs its matching smoke; a smoke's final state is never a
substitute parent. Launch checks code, parents, approval and evidence again
before each history, uses exclusive logs and an attempt lock, records GPU UUID,
name and driver, and stops on the first execution/validation failure. Completion
and failure records are new files; a killed process remains visibly unfinished.

`--smoke` uses the separate candidate-oracle executable and refuses more than
10,000 steps. Ordinary MD has no all-pairs oracle instrumentation. Segment
lengths of at least 3000 steps provide the four diagnostic samples required by
the existing parser; nonaligned endpoints are validated explicitly. Prefer
1000-step-aligned segments and review windows for stationarity. Numerical
verification works on archived plans without demanding that their old source
SHA is today's HEAD; launching always requires the prepared code/build.

The older generic `equilibrate --stage e2 --execute` route is disabled. Historical
C1 launchers and data retain their original behavior/provenance.

## Numerical and scientific review

`kg_assoc_e2_validate.py` derives counts, stickers, geometry, physics, step range,
parents and seeds from the plan. It reuses the validated C1 seeded event replay,
network definitions, restart parsing and snapshot checks. It checks synchronized
absolute cadence, chemistry sweeps, event order/accounting, reciprocal partners,
all recorded network diagnostics (including L1/L2), counters, cumulative distance
observations, permanent identities/box, numerical temperature/velocities and
final chemical/particle mirrors. It never requires a fixed C1 particle/sticker
count or a creation/rupture in a short smoke. Numerical validity is separate
from scientific acceptance.

The E2 executable adds `state.conformation.tsv`, synchronized with state/numerics
at initial, every 1000-step absolute diagnostic and final time. It records mean
star Rg² and mean terminal-to-center R². Permanent-bond BFS minimum-image
unwrapping follows the validated E1 method, uses stable IDs and O(Nbeads) scratch
storage. It samples only at diagnostic times; it adds no bead trajectory, per-MD
step graph scan, pressure estimator or periodic winding claim. Offline endpoint
shape reconstruction independently checks loaded and final observables, allowing
snapshot serialization precision. Existing state/events/sidecar formats remain
loadable; old segments need not contain the newly added conformation file.

`analysis/analyze_e2_segment.py` reviews one complete segment's three histories
in a new `aggregate/e2/<version>` directory. Specify discard and window lengths
explicitly. It reuses exact event-integrated population exposures, accepted
reaction/distinct-neighbor activity, first-nonpositive-lag IAT, trends, 5/10/20
block SEM sensitivity and replica-level/paired Student-t summaries (df=2).
Populations, intra/inter, components, degree/moment, L1/L2 and both shape metrics
are reviewed jointly. Constant observables are flagged as insufficient mixing
evidence; long correlation/broad uncertainty is not an automatic pass.

Outputs are immutable summary/configuration JSON, replica comparison CSV and a
review report. The configuration pins completion records and analyzer dependencies.
No percentage threshold, automatic equilibrium acceptance or automatic extra MD
is introduced. Extend only after explicit review, preserve discarded transients,
and label all segment boundaries. Do not stitch transport, lifetimes or stress
through MD reseeding/folding boundaries; successive segments are the same three
histories, not extra replicas.

## Acceptance and active E2 selection

`e2_acceptance.schema.json` specifies the small immutable acceptance record:
three accepted segment prefixes/steps/chemistry seeds/physics/hashes, source plan,
reviewer/date, evidence/hash, qualification and explicitly permitted system IDs
for `production_initial_state`. Human review is mandatory. Smoke outputs cannot
be accepted. A missing, changed, incomplete or wrong-use record fails closed.

`campaign/kg_assoc_e2_registry.py accept` validates an ordinary completed segment
before writing a new acceptance record. Its `--c1` import authenticates only the
pinned corrected 8M recovery and requires a nonempty slow-topology qualification.
It preserves automated historical `review_required` records, the original 6M
banks and all scientific outputs. `publish` creates a new immutable registry
mapping permitted system IDs to acceptance records and their hashes. Multiple
records may be included in one registry; a new selection requires a new registry
filename rather than editing an existing map.

Production preparation **requires explicit `--e2-registry`** for associating
systems. There is no fallback to `banks/e2/<bank>` or generic `validation.json`.
It stores the resolved registry/acceptance/particle/sidecar hashes and the parent
Ea, then reauthenticates them before a later launch. Nonassociating E1 control
selection remains as before. C1 defective 6M banks are rejected even if generic
historical acceptance metadata exists.

Both E2 and strict campaign production require `--switch-ea-from <parent Ea>`
with a distinct explicit `--Ea <target>` for an Ea change. Wrong parent values,
missing target, implicit changes and wrong Ee fail before integration. The
switch preserves the parent snapshot/network/counters and changes future
kinetics; E2 extensions retain the chemical seed, while production uses its
separately recorded campaign seed. State/event provenance records the parent Ea
and switch flag. `kg_assoc_campaign_production --validate-initial-state` provides
an entirely host-only check of the production request/sidecar; it constructs no
integrator and writes no output.

The native executables remain usable independently; authentication is enforced
by campaign preparation/launch tools, not by parsing a JSON registry in CUDA.
No production execution is part of E2-G1.

## Current validation and limitations

Affected CUDA targets were rebuilt with CUDA12.8/GCC11.2: stars, oracle stars,
ordinary production, campaign production, capped campaign production and the
candidate oracle. Host E2 self-tests cover explicit switch rejection, common-q
probability ratios and translated PBC-safe shape observables. Candidate-search
translation/degenerate-grid/cutoff/active-partner/ordered-kinetics regressions pass.
Host production request checks pass for all three real corrected C1 parents at
Ea=4/6/8/10; absent/wrong-parent switches fail. No GPU was used.

The offline suite includes non-C1 numerical fixtures, seed queries, inherited
partners, malformed/tampered outputs, approval and smoke gates, no overwrite,
fail-fast retention, complete preparation/review/extension manifests, nonaligned
endpoints, reproducible correlation-aware review and mandatory registries. These
are deterministic regression tests, not stochastic convergence experiments.
Run the deterministic suite from the repository root:

```bash
PYTHONPATH=examples/KG_Assoc/campaign:examples/KG_Assoc/analysis \
  python3 -m unittest discover -s examples/KG_Assoc/campaign -p 'test_*.py'
examples/KG_Assoc/kg_assoc_stars --self-test
examples/KG_Assoc/kg_assoc_production --self-test
examples/KG_Assoc/kg_assoc_candidates_test
```

Final test counts and hashes are reported in the delivery.

All 506 frozen data/report files (594,671,885 bytes) were checked unchanged.
No original E1, E2, recovery, historical or production output is overwritten.
Protected `src/*` and `examples/KG/*` were not modified. The kinetics helper and
validated E1 implementation are unchanged; no new physical model is introduced.

GPU execution is unavailable here (`nvidia-smi` cannot communicate with its
driver). Capped revised E2/production GPU tests remain pending. Absolute-path
plans intentionally bind to the prepared dataset/host checkout; relocation
requires a new authenticated plan, not editing one. Numerical invariance,
condition-dependent equilibration times, slow-topology precision targets and
whether to add periodic wrapping measurements remain scientific qualifications
or later review decisions. None silently clears a long-run launch gate.
